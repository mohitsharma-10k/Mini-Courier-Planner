Abstract

Mini-Courier Planner is a Python application that integrates sorting, dynamic programming, graph algorithms and approximation techniques to solve a simplified courier delivery-planning problem. The system receives parcel details, an urban road network and a vehicle payload capacity. It prioritizes parcels, selects a high-value feasible set using 0/1 Knapsack dynamic programming, calculates shortest paths using Dijkstra's algorithm and constructs an approximate delivery tour using the nearest-neighbor TSP heuristic with 2-Opt refinement.

A benchmark mode records runtime measurements across scaling datasets from N = 10 to N = 1000 parcels, while unit tests check algorithmic correctness. The project uses Python's standard library only, running on any machine with Python 3 with zero external dependencies.

1. Introduction and Problem Definition

1.1 Background

Courier planning involves selecting parcels that fit into a delivery vehicle and deciding the order in which delivery locations should be visited. In urban logistics, a dispatcher must resolve several algorithmic problems before dispatch: which parcels are most urgent, which combination of parcels maximizes utility under strict cargo weight limits, how far destinations are across city roads, and what sequence of stops minimizes total transit time and distance.

The problem combines multiple algorithmic paradigms: comparison sorting for priority ordering, 0/1 Knapsack Dynamic Programming for payload optimization, Dijkstra's single-source shortest paths on graphs, and Nearest-Neighbor heuristics refined with 2-Opt local search for Traveling Salesperson Problem (TSP) routing. Each maps directly to core concepts in Design and Analysis of Algorithms.

The system models a realistic urban road network centered around a delivery hub in Gurugram NCR, demonstrating complete operational flow from parcel intake to final vehicle return.

1.2 Formal Problem Statement

Given a set of n customer parcels, a weighted undirected road graph G = (V, E) with a central depot (Node 0) and vehicle cargo payload capacity W = 25.0 kg, the planner must produce a complete delivery plan satisfying the following:

Element Description
Input — parcels For each parcel: ID, recipient name, destination node, weight (kg), value, and delivery deadline (hours).
Input — road network Locations (vertices V) and bidirectional road links (edges E) with physical distances in kilometres.
Input — parameters Depot node (Node 0) and maximum vehicle capacity (default W = 25.0 kg).
Output 1 A prioritized parcel queue sorted deterministically by urgency and priority ratio.
Output 2 An optimal subset of parcels whose combined weight <= W and whose total value is maximized.
Output 3 All-pairs shortest paths and driving distances from the depot to all selected destinations.
Output 4 An optimized delivery tour and trajectory starting and ending at the depot, with total distance and trip time.

1.3 Why These Algorithms

Each stage of the planner uses the algorithmic technique best suited to its sub-problem:

Stage Technique Rationale
Prioritization Merge Sort & Quick Sort Guarantees deterministic, stable ranking in O(n log n) time based on urgency and deadline.
Load selection 0/1 Knapsack (DP) Each parcel is indivisible (0/1); DP guarantees the mathematically optimal value under the capacity ceiling.
Distance computation Dijkstra's algorithm (Min-Heap) Physical road distances are strictly non-negative; Dijkstra computes exact shortest paths in O((V+E) log V).
Route construction Nearest-Neighbor + 2-Opt Exact TSP is NP-hard; NN constructs an initial tour fast, and 2-Opt untangles route crossings to achieve local optimality.

2.1 Assumptions

To keep the model mathematically well defined and tractable, the following assumptions are made:

  • Parcel weights are positive values with discrete resolution (hectograms = 0.1 kg).
  • Higher priority scores and earlier deadlines indicate greater delivery urgency.
  • Each parcel is indivisible: it is either loaded in full or left behind (0/1 constraint).
  • Road segments are undirected with non-negative road distance weights.
  • All selected customer locations are connected and reachable from the central depot.
  • Multiple packages delivered to the same destination are consolidated into one stop.
  • The delivery van departs from and returns to the Central Depot (Node 0).

3. System Design and Workflow

The program is organized into modular packages. Algorithms are executed in a pipelined fashion: input datasets are loaded, parcels are ranked, knapsack packing is computed, shortest paths are derived, and the TSP tour is optimized and displayed.

The workflow has five stages: (1) load parcels and graph topology; (2) rank parcels using Merge/Quick sort; (3) run 0/1 Knapsack DP; (4) run Dijkstra from Depot to selected stops; and (5) build and refine the TSP tour with 2-Opt. Figure 1 shows this flow.

4. Algorithms and Complexity Analysis

This section describes the four algorithmic components, gives their pseudocode, and analyzes their time and space complexity. Throughout, n is the number of parcels, W is the integer capacity in hectograms (250 units), V and E are the numbers of vertices and edges in the road graph, and k is the number of unique delivery stops.

4.1 Parcel Prioritization — Comparison Sorting

Parcels are sorted by descending composite Priority Ratio. Two algorithms were evaluated: Merge Sort (guaranteed O(n log n) divide-and-conquer, stable) and Quick Sort (median-of-three pivot selection). On the sample dataset of N = 10 parcels, Merge Sort performed 23 comparisons and 34 assignments, while Quick Sort required 28 comparisons and 16 swaps.

SORT-PARCELS(parcels): # Sorts by composite priority ratio descending, then ID return sorted(parcels, key = lambda p: (-p.priority_ratio, p.parcel_id))

In the sample data, parcel P108 (Express Documents) achieves the highest ratio (22.22) due to low weight (1.5 kg) and high value (60), followed by urgent medical supplies P103 (ratio 13.33). Sorting establishes urgency ordering before packing.

4.2 Package Selection — 0/1 Knapsack Dynamic Programming

Let dp[i][c] denote the maximum value obtainable using the first i parcels with available vehicle capacity c. If parcel i has weight w and value v, then if w > c the parcel cannot fit and the previous value is retained. Otherwise, the optimal choice is the maximum of excluding the parcel and including it.

Recurrence
dp[i][c] = dp[i−1][c] if w > c
dp[i][c] = max( dp[i−1][c], v + dp[i−1][c−w] ) otherwise

KNAPSACK(parcels, W): dp[0..n][0..W] = 0 for i = 1 to n: for c = 0 to W: dp[i][c] = dp[i-1][c] if weight[i] <= c: dp[i][c] = max(dp[i][c], value[i] + dp[i-1][c - weight[i]]) # trace back from dp[n][W] to recover the chosen parcels c = W for i = n down to 1: if dp[i][c] != dp[i-1][c]: select parcel i; c = c - weight[i] return selected, dp[n][W]

Time complexity: O(nW). Space complexity: O(nW), where n is the number of parcels and W is the vehicle capacity (250 discrete hectogram units for 25.0 kg). The algorithm is pseudo-polynomial: its running time scales with the numeric capacity W.

A naive greedy approach that loads parcels purely by value-to-weight ratio can leave stranded capacity gaps. Dynamic Programming considers every subproblem combination and guarantees the global optimal selection.

4.3 Graph Representation and Dijkstra's Algorithm

The urban road network is represented using an Adjacency List. Each vertex stores its incident neighbors along with road edge distances. This uses O(V + E) space, which is optimal for sparse urban road networks where |E| << |V|^2. Dijkstra's algorithm uses a binary min-heap (heapq) to compute shortest driving paths from the central depot (Node 0) to all customer stops.

DIJKSTRA(graph, source): dist[v] = infinity for all v; dist[source] = 0 heap = [(0, source)] while heap is not empty: (d, u) = extract-min(heap) if d > dist[u]: continue for (v, w) in graph[u]: if dist[u] + w < dist[v]: dist[v] = dist[u] + w; prev[v] = u push(heap, (dist[v], v)) return dist, prev # prev lets us rebuild each road path

With a binary heap, Dijkstra executes in O((V + E) log V) time. The predecessor map prev enables exact physical trajectory reconstruction across intermediate intersections (e.g. Depot -> MG Road -> Cyber City).

4.4 Delivery Tour — Nearest-Neighbor TSP Heuristic

The route begins at Depot (Node 0). At each step, the algorithm chooses the closest unvisited delivery node using Dijkstra distances. After visiting all stops, it returns to Depot. The initial tour is then passed to a 2-Opt local search refinement routine that evaluates pairwise edge swaps to untangle crossing paths and guarantee local optimality.

TSP-SOLVER(graph, depot, stops): tour = NEAREST-NEIGHBOR(graph, depot, stops) improved = True while improved: improved = False for i in 1..k-1: for j in i+1..k: if distance(2-opt swap of i..j) < distance(tour): tour = perform_2opt_swap(tour, i, j) improved = True return tour

For K customer stops, Nearest-Neighbor runs in O(K^2) time, and 2-Opt completes in polynomial time O(iter * K^2), avoiding the O(K!) brute-force explosion.

9. Conclusion

Mini-Courier Planner successfully implements and evaluates an integrated algorithmic solution to urban logistics challenges. The system combines comparison sorting for urgency ranking, 0/1 Knapsack Dynamic Programming for vehicle payload optimization, Dijkstra's algorithm for shortest-path road navigation, and Nearest-Neighbor TSP with 2-Opt refinement for route construction.

In the baseline execution, the system selected 6 parcels totaling 24.70 kg (98.8% capacity utilization), accumulated 505 value points, and generated an optimal 25.50 km round trip taking 76.0 minutes. Multi-scale benchmarking demonstrated sub-40ms execution up to 1000 parcels.

Key learnings from the project:

  • Selecting the correct algorithmic paradigm for each sub-problem is paramount.
  • Dynamic Programming provides mathematical optimality where greedy heuristics fail.
  • Min-heap priority queues make graph explorations efficient on sparse road topologies.
  • 2-Opt local search offers polynomial-time tour refinement for NP-hard routing problems.
